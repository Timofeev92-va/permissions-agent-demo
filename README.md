# Permissions Agent (демо)

Инструмент для контроля разрешительной документации персонала на крупном промышленном проекте (подрядные работы, вахтовый метод).

> Это обезличенная демо-версия реального рабочего инструмента. Все имена, названия компаний, номера договоров и документы в этом репозитории — синтетические, созданы для демонстрации подхода и не содержат реальных персональных или коммерческих данных.

## Задача

У заказчика — десятки требований к документам персонала (промышленная безопасность, электробезопасность, медосмотры, ГНВП, работы на высоте и т.д.), каждое со своим сроком действия и источником (раскидано по нескольким приложениям к договору). Нужно было:

1. Свести все требования из договорной документации в единый чек-лист.
2. Сопоставить чек-лист с фактическим пакетом документов каждого сотрудника.
3. Увидеть на одной странице, что просрочено, что истекает скоро и чего не хватает вообще.

## Что сделано

- **Пайплайн распознавания** (`extract_docs.py`): пакетная обработка сканов документов — сначала попытка извлечь текст напрямую из PDF (`pypdf`), при неудаче — рендер страницы (`pdftoppm`) и OCR (`tesseract`, рус+англ). Из текста и имени файла извлекается тип документа, дата выдачи и автоматически считается дата истечения по справочнику сроков действия.
- **База знаний требований** (`permissions/requirements.md`) — сведённый из разных приложений к договору перечень обязательных документов со сроками действия.
- **Отчёт по сотрудникам** (`permissions/gaps.md`, `permissions/*.json`) — автоматически сформированный статус по каждому документу: ОК / истекает через N дней / просрочен / отсутствует.
- **Прототип интерфейса** (`permits-mockups/`) — дашборд со сводкой по всем сотрудникам, карточка сотрудника с перечнем документов, экран загрузки нового документа, архив для формирования пакета на отправку заказчику.

## Стек

Python (pypdf, tesseract OCR через subprocess), JSON как формат базы знаний, HTML/Tailwind для прототипа интерфейса.

## Структура репозитория

```
extract_docs.py              — скрипт распознавания и структурирования документов
permissions/
  requirements.md            — сведённые требования заказчика (пример)
  gaps.md                    — отчёт по сотрудникам (пример)
  employee_a.json, employee_b.json, all_docs.json  — пример результата OCR-пайплайна
permits-mockups/             — HTML-прототипы интерфейса (дашборд, карточка сотрудника, загрузка, архив)
sample_data/                 — пустые папки под входные сканы (в реальном проекте — PDF/JPG документов)
```
